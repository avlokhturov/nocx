# Restore: the application opens on what you left — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: `beads-superpowers:executing-plans` (or `subagent-driven-development`). Each Task becomes a bead under epic `nocx-l21ib`.

**Goal:** quit with tabs across workspaces and reopen to find them — in their workspaces, in their directories, with their blocks and the output those blocks printed.

**Architecture:** restore is a query over the ledger by `pane_id`, not a snapshot store (ADR-0019 §3). The chain already comes back (nocx-isoph.4) and the bodies are already written (nocx-2f0f); what is missing is a pane's cwd being kept current, the read being expressible on the wire, a block that can be built from the store instead of from a terminal buffer, and a setting that turns the whole thing off.

**Tech stack:** Go (`internal/content`, `internal/transport`, `internal/settings`), TypeScript + vitest (renderer), Playwright (e2e), JSON Schema in `contracts/`.

## Global constraints

- **Spec:** `.internal/specs/2026-08-19-restore-and-output-capture-design.md` §5, §6, §7.
- **ADR-0019 §3:** live resumption may not be implied. A restored block is visibly not a live one.
- **ADR-0019 §7:** reconstruction states its own horizon. An evicted body renders as a marker, never as a command that printed nothing.
- **D5:** the process is never resurrected. A local pane starts a fresh shell in the restored cwd; a cwd that is gone falls back to home.
- **AD-8:** one owner per behaviour. `ledger.query` stays the single ordering implementation; the serializer's attribute→style mapping stays the single appearance owner.
- **Out:** process resurrection, inline-`ssh` restoration, undo-close, paging older blocks upward, multi-window.

### Task 1: The pane's directory is kept current

**Files:** `internal/content/layout.go` (+`_sqlite`, `stub`), `internal/transport/ws_layout_handlers.go`, `frontend/src/layout/layout-client.ts`, `frontend/src/terminal-content.ts`; tests beside each.

**Why:** `Pane.Cwd` is written once at creation and never revised — `layout.go` says so in as many words — so a restored local pane would open wherever the pane was first created rather than where it was left.

**Acceptance criteria:**

- `SetPaneCwd(ctx, paneID, cwd)` writes the column and answers `ErrNoSuchPane` for an id no pane carries.
- `panes.setCwd` validates the id as a UUIDv7 and bounds the path; it is idempotent — the same cwd twice writes once.
- The renderer calls it on a VERIFIED OSC 7 report only (`_cwdVerified`), never on the session-open fallback, which is a provider's guess and not a fact.
- A test drives a cwd change through the renderer seam and reads the stored row back.

### Task 2: `ledger.query` can ask for one pane's blocks

**Files:** `internal/transport/ws_ledger_query.go`, `contracts/ledger.query.schema.json` (description only), tests.

**Why:** `content.LedgerQuery.PaneID` exists and `QueryEntries` honours it; only the wire cannot express it. One ordering implementation, not a second read.

**Acceptance criteria:**

- `paneId` is accepted, validated as a UUIDv7, and narrows the page to that pane's entries.
- Absent `paneId` behaves exactly as today.
- Over the wire: two panes' blocks are recorded and each query returns only its own, newest first.

### Task 3: A block can be built from the store

**Files:** `frontend/src/scrollback/sgr-read.ts`, `frontend/src/scrollback/restored-block.ts`, `frontend/src/styles/components/*.css`; tests.

**Why:** `blocks.ts` builds a block from `IBufferLine`s. A restored block has no buffer — it has an entry's facts and an SGR body.

**Acceptance criteria:**

- `attrsFromSGR` turns `\x1b[31m` and the 256/24-bit forms back into the serializer's `CellAttrs`, and an unknown parameter is ignored rather than fatal.
- The HTML a restored body renders to is identical to what the same rows produced live, under the same theme — one mapping, asserted by round-tripping a serialized range.
- A restored block carries `data-restored`, shows the command, cwd, status, exit code and duration, and offers no action that needs a process.
- A block whose body is absent renders an honest marker, not empty output.

### Task 4: A pane asks for its blocks when it is first shown

**Files:** `frontend/src/restore-client.ts`, `frontend/src/panes.ts`, `frontend/src/terminal-content.ts`; tests.

**Acceptance criteria:**

- The newest 50 entries for the pane are fetched when its content is first shown, not at boot: eight panes at fifty blocks is four hundred blocks of DOM before the first frame.
- They render oldest-first above an explicit boundary that separates them from the live shell.
- The bodies are fetched per block through `ledger.get` + the artifact read, and a block whose artifact is gone shows the marker from Task 3.
- With the content store degraded to the stub the tabs still come back and the product SAYS history is unavailable — through the surface `nocx-rtg0.19` built, not a log line.

### Task 5: The setting, and the OFF path

**Files:** `internal/settings/settings.go`, `internal/app/app.go`, `frontend/src/main.tsx`; tests.

**Acceptance criteria:**

- `restore.onStartup`, General section, default ON.
- OFF: boot opens one fresh local tab and asks the chain for nothing — the stored rows are left alone, so turning it back on restores what was there.
- A test asserts both directions at the renderer seam.

### Task 6: ssh panes reconnect

**Files:** `frontend/src/panes.ts`; tests. **Blocked by `nocx-o9jdu`** — eight panes reconnecting behind a sealed vault raise eight unlocks and seven are already answered by the first.

**Acceptance criteria:**

- A pane whose kind is `ssh` reopens against its stored endpoint; a failure leaves the pane with its blocks and a visible reason, never a silent local shell.
- An inline `ssh` is untouched: the pane comes back local, and its blocks keep the host they recorded.

### Task 7: The epic's happy path

**Files:** `e2e/restore.spec.ts`.

**Acceptance criteria:**

- Eight tabs across three workspaces (one default, two named and coloured), commands run in them, backend restarted, page reloaded: every tab returns in its workspace with its name and colour, every pane in its directory, every block with its command and its output.
- With the setting off, the same restart gives one fresh local tab.
- Verified to FAIL on a build with the restore read removed — the check that separates this from a spec that would have passed anyway.
